# PRD — 태양의 호텔 (호텔 예약 시스템)

- 기준: dev 브랜치, 2026-11-24
- 해커톤: 3기 바이브코딩 해커톤(11-19 ~ 11-26), 5인 팀
- 관련 문서: [TECH_SPEC](TECH_SPEC.md) · [WORK_UNITS](WORK_UNITS.md) · [FINAL_CHECKLIST](FINAL_CHECKLIST.md) · [시스템 구조 그림](../docs/ARCHITECTURE.md)

## 1. 한 줄 소개

손님은 날짜와 인원을 넣으면 **예약 가능한 객실을 추천받아 바로 예약**하고, 관리자는 **객실 · 휴무일 · 예약 승인**을 한 화면씩 관리하는 호텔 예약 서비스입니다.

## 2. 문제

| 누가 | 지금 불편한 점 |
|---|---|
| 손님 | 빈방을 찾으려면 날짜를 바꿔 가며 객실을 하나씩 확인해야 한다. 어떤 방이 인기 있는지 알기 어렵다 |
| 관리자 | 객실 정보, 공사 · 점검으로 쉬는 날, 예약 승인이 따로 관리되어, 쉬는 날에 예약이 들어오는 등 어긋나기 쉽다 |

## 3. 목표

1. 손님이 **날짜 · 인원만으로 예약 가능한 객실**을 보고, 그 자리에서 예약을 신청한다.
2. 관리자가 지정한 **휴무일은 추천 · 예약에서 자동으로 막힌다.**
3. 관리자는 예약을 **승인 · 취소**하고, 상태가 손님 화면에 바로 반영된다.

**하지 않는 것(이번 해커톤):** 결제, 성수기 요금, 회원 등급 · 할인, 이메일 · 문자 알림, 다국어.

## 4. 사용자와 역할

| 역할 | 할 수 있는 것 |
|---|---|
| 손님(`USER`) | 회원가입 · 로그인, 객실 추천, 예약 신청, 내 예약 보기, 내 정보 수정 · 비밀번호 변경 · 탈퇴 |
| 관리자(`ADMIN`) | 객실 관리, 예약 일자(휴무일) 관리, 예약 관리(승인 · 취소) |
| 로그인 안 한 사람 | 객실 추천 보기, 회원가입 · 로그인 · 비밀번호 찾기 |

## 5. 화면과 기능 (5개 파트)

| 파트 | 화면 코드 | 화면 | 핵심 기능 |
|---|---|---|---|
| 1 회원 · 객실 추천 | ROOM-001 | `/rooms`, `/login`, `/signup`, `/mypage`, `/password-reset` | 날짜 · 인원으로 예약 가능한 객실만, 추천순(점수 0~100) · 인기순 · 낮은 가격순, 1등 "추천" 표시 |
| 2 객실 관리 | ADM-001 | `/admin/rooms` | 객실 추가 · 수정 · 사용/비활성, 사진(jpg · png, 최대 5장, 첫 장 대표), 요약 카드, 앞으로 묵을 예약이 있으면 종류 · 인원 · 요금 수정 불가 |
| 3 예약 일자 관리 | ADM-002 | `/admin/closed-dates` | 달력에 휴무 · 예약 수 · 남은 객실 수, 호텔 전체 / 객실별 휴무 지정 · 해제, 기간 지정(최대 31일) · 기간 해제, Shift+클릭 |
| 4 객실 예약 · 완료 | RSV-001, RSV-002 | `/reservation/new`, `/reservation/{id}/complete`, `/reservation/list` | 예약 신청(인원 · 휴무 · 겹침 검사, 금액은 서버 계산), 완료 화면, 내 예약 |
| 5 공통 · 예약 관리 | ADM-003 | `/admin/reservations`, 상단 메뉴 | 상태 · 기간 · 검색으로 예약 목록, 승인 · 취소, 역할별 메뉴(DB) |

## 6. 핵심 규칙

| 규칙 | 내용 |
|---|---|
| 예약이 차지하는 날 | 체크인 ≤ 날짜 < 체크아웃. **체크아웃 날은 다음 손님이 체크인할 수 있다** |
| 살아 있는 예약 | 대기(`PENDING`) · 승인(`APPROVED`). 취소(`CANCELED`)는 객실을 잡지 않는다 |
| 예약 상태 | 대기 → 승인 / 취소, 승인 → 취소. 취소는 되돌릴 수 없다. 체크인이 지난 예약은 취소 불가 |
| 휴무 | `room_id`가 비면 호텔 전체 휴무, 있으면 그 객실만. 그날 묵는 예약이 있으면 지정 불가 |
| 휴무와 추천 · 예약 | 숙박 기간에 휴무가 하루라도 끼면 추천에서 빠지고 예약은 409 |
| 추천 점수 | (조회수 ÷ 최대 조회수) × 30 + (최근 30일 예약 수 ÷ 최대값) × 70. 판매 중인 객실 전체 기준 |
| 오늘 | 한국 시간(KST) |

## 8. 성공 기준

- 시연 시나리오(추천 → 예약 → 관리자 승인 → 휴무 지정 → 추천에서 빠짐)가 한 번에 끝까지 동작한다.
- 백엔드 테스트(`uv run pytest`)와 프론트 빌드(`npm run build`)가 통과한다.
- [FINAL_CHECKLIST](FINAL_CHECKLIST.md)의 필수 항목이 모두 체크된다.
